# Effort Lab

**작업에 맞는 AI 추론 수준과 문맥을 선택하고, 실제 토큰 사용량과 정답률을 비교하는 로컬 데스크톱 앱입니다.**

간단한 변환과 복잡한 추론에 같은 `high` effort를 쓰는 낭비를 줄이는 것이 목표입니다. 로컬 규칙으로 시작 수준을 정하고, 검증에 실패하면 effort를 높입니다. 실패한 호출의 비용도 모두 기록합니다.

Spring Boot · Java 21 · React · TypeScript · Electron · H2

[기획서](docs/기획서.md) · [묶음 실측](docs/묶음실측결과.md) · [추론 예산 연구](docs/추론예산연구.md) · [Releases](https://github.com/minseokKim6823/effort_lab/releases)

## 다운로드와 시작

[GitHub Releases](https://github.com/minseokKim6823/effort_lab/releases)에서 **Windows x64**용 파일을 받으세요. 파일이 아직 표시되지 않으면 아래 소스 실행 방법을 사용할 수 있습니다.

| 파일 | 용도 |
|---|---|
| `Effort-Lab-Setup-0.2.0-x64.exe` | 설치형. 설치 후 시작 메뉴에서 Effort Lab 실행 |
| `Effort-Lab-0.2.0-portable-x64.exe` | 설치 없이 실행하는 포터블 |
| `SHA256SUMS.txt` | 다운로드 파일의 SHA-256 확인 |

**데스크톱 패키지에는 Java 21, Node 런타임, Codex CLI가 포함됩니다. 별도 설치는 필요하지 않습니다.**

1. 설치 파일 또는 포터블 파일을 실행합니다. 첫 실행에는 로컬 서버 준비 시간이 필요합니다.
2. 앱 메뉴에서 **Effort Lab → Codex 로그인**을 선택합니다. 기존 Codex 로그인이 있으면 그대로 사용합니다.
3. **로그인 상태 확인** 메뉴로 연결을 확인합니다.
4. 먼저 **데모 · 시뮬레이션**으로 사용법을 살펴본 뒤, **Codex 구독 · 실제 측정**을 선택합니다.

실제 모델 실행에는 이용 가능한 Codex 구독과 인터넷 연결이 필요합니다. **별도 OpenAI API 키는 필요하지 않습니다.** 앱을 열거나 effort만 분석할 때는 모델을 호출하지 않습니다. 실제 실행은 구독 사용량을 소비하며, 데모 수치는 실측 결과가 아닙니다.

배포 파일은 코드 서명되지 않아 Windows가 알 수 없는 게시자로 표시할 수 있습니다. 아래 명령으로 받은 파일을 확인하고, 같은 릴리스의 `SHA256SUMS.txt`와 비교하세요.

```powershell
Get-FileHash .\Effort-Lab-Setup-0.2.0-x64.exe -Algorithm SHA256
```

## 실제로 얼마나 줄었나

**독립 작업 묶음 실행의 효과는 관측했지만, 자동 effort 선택의 개선은 아직 입증하지 못했습니다.**

새로운 24개 합성 문제에서 같은 `high` effort로 개별 호출 24회와 네 문제씩 묶은 호출 6회를 비교했습니다. 두 방식 모두 24/24 정답이었고 총토큰은 **95,440 → 32,665(65.77% 감소)**였습니다. 반복 문맥을 공유해 입력 토큰이 87,784 → 23,975로 줄었습니다. 문제당 한 번씩 실행했으며, 12개 기존 유형의 새 인스턴스이므로 실제 업무나 다른 작업 유형의 품질 유지로 일반화할 수 없습니다. [조건·원본·감사 결과](docs/묶음실측결과.md)를 공개합니다.

같은 24문제의 개별 호출에서 `low`는 **98,979토큰·19/24 정답**으로, `high`의 **95,440토큰·24/24 정답**보다 토큰을 **3.71% 더 사용**하고 5문제를 더 틀렸습니다. 한 번씩 다른 시점에 실행한 탐색적 비교이며, 낮은 effort가 항상 저렴하다는 가정도 성립하지 않았습니다. [후속 계획·원본·독립 감사](docs/개별-effort-후속결과.md)를 공개합니다. 기존 자동 정책의 성과는 아래와 같습니다.

확장 12문제의 **완료된 첫 번째 반복** 결과입니다. 모델은 `gpt-5.6-luna`이며, 정답은 코드로 계산하고 실험 전에 고정했습니다.

| 실행 방식 | 총토큰 | 정답 수 |
|---|---:|---:|
| 기존 문맥 · high | 86,839 | 11 / 12 |
| 짧은 문맥 · high | 46,656 | 11 / 12 |
| 짧은 문맥 · low | 44,093 | 11 / 12 |
| 짧은 문맥 · 자동 effort | 48,667 | 10 / 12 |

같은 high에서 문맥을 줄였을 때 총토큰이 **46.27% 감소**했고 정답 수는 같았습니다. 반면 자동 effort는 짧은 문맥 high보다 토큰을 **4.31% 더 사용**하고 정답 수도 적었습니다. 전체 감소를 effort 선택의 성과로 표현하지 않습니다.

계획은 12문제 × 3회 × 4전략 = 144개 실행이었지만, 84번째 기록에서 구독 사용량 한도로 중단됐고 마지막 호출의 usage가 누락됐습니다. 따라서 위 표는 **완료된 1회차의 제한적인 관찰**이며, 전체 반복 실험의 확정된 절감률이나 일반적인 품질 유지의 증거가 아닙니다. 중단된 결과와 실패 사례도 공개합니다.

[측정 조건과 실패 사례](docs/개선실측결과.md) · [원본 보고서](results/v2/report.json) · [원본 JSONL](results/v2/traces) · [독립 감사 결과](results/v2/observed-audit.json)

기존 기초 실험의 0.21% 차이도 [이전 보고서](docs/실측결과.md)에 보존했습니다.

## 작동 방식

1. **선택:** 변환·추출은 low, 계산은 medium, 복잡한 추론 신호나 정확도 우선은 high로 시작합니다. 로컬 규칙이므로 선택에 쓰는 AI 토큰은 0입니다.
2. **실행:** 답변 전용 작업에는 짧은 지시문으로 같은 모델을 호출합니다.
3. **검증:** 정답 일치·필수 문자열·JSON 형식 중 지정한 기준으로 확인합니다. 기준이 없으면 `UNVERIFIED`로 표시합니다.
4. **재시도:** 검증에 실패하면 다음 effort로 올립니다. high까지 최대 세 번이며, 모든 입력·출력 토큰을 합산합니다.
5. **비교:** 기존 문맥 high와 짧은 문맥의 high·low·자동을 비교해 문맥 효과와 effort 효과를 분리합니다.

JSON 형식 검사는 내용의 정확성을 보장하지 않습니다. 키워드 규칙도 작업 난이도를 완벽히 예측하지 못합니다. 이 앱은 자체 요청을 조절하며, 기존 Codex 앱 전체의 대화 설정을 변경하는 플러그인은 아닙니다.

## 소스에서 실행

개발할 때는 **Java 21**, **Node.js 22.12 이상**, 로그인된 Codex CLI가 필요합니다. Gradle wrapper는 저장소에 포함되어 있습니다.

```powershell
npm install -g @openai/codex@0.153.4
codex login
codex login status
```

터미널 1:

```powershell
cd backend
.\gradlew.bat bootRun
```

터미널 2:

```powershell
cd frontend
npm ci
npm run dev
```

브라우저: http://127.0.0.1:5173

백엔드: http://127.0.0.1:8087/api/status

Windows npm 전역 설치 경로를 자동 감지합니다. 다른 설치 방식은 환경변수로 지정합니다. 모델 이용 가능 여부는 계정과 환경에 따라 확인해야 합니다.

```powershell
$env:CODEX_JS_PATH = 'Codex 설치 폴더/bin/codex.js'
$env:CODEX_MODEL = 'gpt-5.6-luna'
$env:NODE_BINARY = 'node'
```

프로젝트 루트의 `start-local.ps1`로 개발 서버 두 개를 함께 시작할 수도 있습니다.

## 테스트와 패키징

```powershell
npm ci --prefix frontend
npm test --prefix frontend
npm run build --prefix frontend
.\backend\gradlew.bat -p backend test bootJar

# 개발 서버가 실행 중일 때 브라우저 테스트
npm run test:e2e --prefix frontend

# Windows 설치형·포터블 빌드와 패키지 실행 검증
.\scripts\build-desktop.ps1
```

설치 파일은 `release/`에 생성됩니다. 패키지 실행 검증은 데모를 사용하므로 구독이나 API 키가 필요하지 않습니다. Java 다운로드는 고정된 SHA-256으로 검증합니다.

`v*` 태그를 푸시하면 GitHub Actions가 Windows에서 빌드·검증한 뒤 설치 파일과 체크섬을 Releases에 게시합니다.

## 데이터와 측정 기준

- 총토큰은 **입력 + 출력**입니다. 추론 토큰은 출력에 포함되므로 다시 더하지 않습니다. 캐시 입력과 실패한 재시도도 집계합니다.
- 정답은 로컬 검증기에만 전달하고 모델 프롬프트에 넣지 않습니다.
- 총토큰 중단 기준은 호출 사이에 검사하므로 마지막 호출만큼 초과할 수 있습니다.
- 사용량이 누락되면 완전한 비교나 확정된 절감률로 표시하지 않습니다.
- 호출 전 오류가 난 실험만 완료된 호출을 보존해 재개할 수 있습니다. 사용량이 불명확하면 재개를 막습니다.
- 개발 실행의 데이터는 `backend/data/`, 데스크톱의 데이터는 사용자 앱 데이터 폴더에 저장합니다. 원문에는 입력 작업과 응답이 포함되므로 공유 전에 내용을 확인하세요.
- 서버는 127.0.0.1에 바인딩합니다. 데스크톱은 임의 포트와 실행마다 생성한 세션 토큰을 사용하고, 종료 시 자체 백엔드와 하위 CLI를 정리합니다.
- 토큰 감소율은 결제 금액이나 남은 구독 한도 감소율과 같지 않습니다.
