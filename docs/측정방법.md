# 측정 방법

## 무엇을 비교하는가

동일한 모델과 동일한 문제를 아래 전략으로 실행한다.

- HIGH: 항상 high, 1회 실행
- LOW: 항상 low, 1회 실행
- ADAPTIVE: 로컬 규칙의 시작 effort, 검증 실패 시 다음 effort로 재시도

각 호출은 새 Codex 세션이다. 동일한 공통 지시문을 붙이고 정답은 모델에 보내지 않는다.
문제와 반복 번호에 따라 실행 순서를 순환한다. 서버와 CLI 버전, 모델, 정책, 문제 버전을 보고서에 기록한다.

예제 12개는 기능·계측 검증용으로 제작했다. 키워드 규칙과 같은 개발 과정에서 만든 문제이므로 독립 평가셋이 아니다. “추론”이라는 그룹명은 실제 고난도를 보증하지 않는다.

## 계산식

- 호출 총토큰 = input_tokens + output_tokens
- 전략 총토큰 = 최초 호출과 모든 재시도의 호출 총토큰 합
- 절감률 = (HIGH 총토큰 − ADAPTIVE 총토큰) / HIGH 총토큰 × 100
- 정답률 = 정답 일치 건수 / 실행된 문제 건수
- 성공당 토큰 = 전략 전체 토큰 / 성공 건수
- 평균 시간 = 문제당 모든 시도의 실행 시간 합의 평균

reasoning_output_tokens는 출력의 세부 항목으로 별도 표시하고 총토큰에 다시 더하지 않는다.
cached_input_tokens는 input_tokens에 포함되므로 총토큰에서 빼지 않는다. 캐시 토큰 수를 함께 제공해 실행 순서와 캐시의 영향을 확인한다.

출력 토큰 절감률과 총토큰 절감률을 구분한다. Codex에는 고정 입력 비용이 있으므로 출력이 크게 줄어도 전체 절감률은 작을 수 있다.
구독 사용량은 요금 청구 금액과 다르므로 달러 절감액으로 바꾸지 않는다.

## 실패와 중단

검증 실패를 숨기지 않는다. 품질을 충족하지 못한 실행도 사용량에 포함한다.
CLI 실패·시간 초과에 사용량이 없으면 미확인 상태로 표시한다. 앞선 호출에서 확인한 사용량은 유지한다.
모든 전략이 완료되지 않은 보고서는 절감률을 확정하지 않는다.

토큰 중단 기준은 호출 사이에 적용하는 소프트 기준이다. 진행 중인 한 호출만큼 초과할 수 있다.
사용자 중단은 현재 호출이 끝난 뒤 적용해 해당 사용량을 기록한다.
서버가 비정상 종료하면 마지막 호출 사용량이 누락될 수 있으므로 이력을 중단 상태로 복구한다.

## 재현

1. codex login status로 구독 로그인을 확인한다.
2. README대로 앱을 실행한다.
3. 비교 실험에서 Codex 구독 모드, 12개 문제, 1회 반복, 350000 토큰 기준을 선택한다.
4. 완료된 보고서 JSON과 backend/data/cli-traces/*.jsonl을 보관한다.
5. 모델 출력은 비결정적이며 서버 환경·캐시에 따라 다음 실행과 수치가 달라질 수 있다.

기존 실측 JSON은 results/ 폴더에 보관한다. 사용자에게 보여주는 절감률은 이 데이터에서 계산한다.
