# 독립 작업 묶음 실행 실측

2026-10-04 측정. 같은 모델 `gpt-5.6-luna`, `high` effort, 답변 전용 문맥을 사용했다. 12개 합성 문제 유형에서 새 인스턴스를 두 개씩 만들어 총 24개를 고정했다. 각 문제를 개별 호출로 한 번, 네 문제씩 묶은 호출로 한 번 실행했다. 정답은 모델에 보내지 않고 응답 후 코드로 채점했다. 자동 재시도와 도구 사용은 없었다.

| 방식 | 호출 | 입력 토큰 | 출력 토큰 | 총토큰 | 정답 |
|---|---:|---:|---:|---:|---:|
| 개별 `high` | 24 | 87,784 | 7,656 | 95,440 | 24/24 |
| 4개씩 묶음 `high` | 6 | 23,975 | 8,690 | 32,665 | 24/24 |

총토큰은 **65.77%**, 입력 토큰은 **72.69%** 감소했다. 묶음의 출력은 1,034토큰 증가했지만 반복되는 입력 문맥을 공유한 이득이 더 컸다. 30개 호출의 원본 JSONL, 사용량, ID, 답안, 채점을 [독립 감사기](../scripts/audit-batch.mjs)로 다시 확인했다. [감사 결과](../results/v3/metrics.json), [실험 계획](배치실험계획.md), [고정 문제](../results/v3/cases.json), [원본 호출](../results/v3/requests), [원본 JSONL](../results/v3/traces)을 공개한다.

이 절감은 **여러 독립 작업을 한 요청으로 합친 효과**다. 개별 작업의 effort 선택이 개선되었다는 뜻이 아니다. 각 팔은 문제당 한 번만 실행했고, 같은 유형에서 숫자와 문자열을 바꾼 합성 문제다. 실제 업무와 긴 답변, 작업 간 의존성, 더 큰 묶음에는 그대로 일반화할 수 없다. 구독 한도나 요금의 절감률도 총토큰 감소율과 같다고 볼 수 없다.

## 재현과 감사

```powershell
node scripts/generate-batch-cases.mjs --check
node scripts/audit-batch.mjs
```

감사는 기존 응답을 읽으므로 새 모델 호출이 없다. 새 측정은 별도 구독 사용량을 소비한다. 전체 비용에는 실패 호출도 포함한다는 규칙을 사용했으며, 이번 30개 호출에는 파싱 실패와 사용량 누락이 없었다.
