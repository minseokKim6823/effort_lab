# 개별 effort 후속 실험 사전 계획

2026-10-04 작성. 배치 실험은 공통 입력 비용을 줄이는 방법이며, 사용자가 요구한 개별 작업의 effort 선택 성능을 직접 증명하지 않는다. 이 후속 실험은 같은 작업을 LOW로 실행했을 때 HIGH 대비 비용과 정확도가 어떻게 달라지는지 측정한다. 계획과 실행기 파일을 확정한 뒤에만 LOW 모델 호출을 시작한다.

## 고정 비교

- 기준선은 results/v3의 SINGLE_HIGH 24회다. BATCH_HIGH는 이 비교에 포함하지 않는다.
- results/v3/cases.json의 24개 문제를 모두 b01부터 b24까지 실행한다. 기존 12개 유형의 두 신규 사례이며, 결과에 따른 문제 선택·제외는 없다.
- 각 SINGLE_HIGH 기록에 저장된 실제 prompt 문자열을 그대로 재사용한다. 동일한 마지막 한국어 지시문을 붙여 stdin으로 보낸다.
- 모델 gpt-5.6-luna, desktop에 고정된 Codex CLI 0.153.4, answer-only-v1, 단건 JSON wrapper를 유지하고 model_reasoning_effort만 high에서 low로 바꾼다.
- 동일한 .tools/batch-measurement/data/runner 작업 경로와 answer-instructions.txt를 사용한다. 지시문 파일이 기준선 manifest의 해시와 다르면 시작하지 않는다.
- 사용자 설정을 무시하고 ephemeral·read-only·web_search disabled를 적용한다. shell_tool·apps·multi_agent를 끈다. API key 환경변수는 제거하고 기존 Codex 구독 로그인을 사용한다.
- 정답은 모델 입력에 넣지 않는다. 생성 결과를 엄격한 ID/문자열 JSON 형식으로 파싱한 다음 로컬에서 채점한다.

## 실행과 예산

v3의 예정된 30회가 모두 완료되고 사용량이 알려진 뒤 후속 24회를 실행한다. HIGH와 LOW를 실행하는 시점이 다르므로 실행 순서, 서비스 상태, 캐시의 영향을 분리할 수 없다. 이는 사전에 정한 탐색적 후속 비교이며, 팔을 교차·무작위 배정한 확증 실험이 아니다.

추가 예산 기준은 실제 입력+출력 110,000토큰이다. 각 요청 사이에 확인하며 기준에 도달하면 다음 요청을 시작하지 않는다. 마지막 호출의 실제 출력 길이는 사전에 알 수 없어 기준을 넘을 수 있다. 한 호출은 최대 180초 기다린다. 시간 초과·중단 때는 이 실행기가 시작한 자식 프로세스 트리만 종료한다.

재시도는 하지 않는다. 의미상 오답은 FAIL로 기록하고 다음 문제를 진행한다. 호출 실패·잘못된 JSON·ID 불일치·도구 사용·사용량 누락은 기록 후 중단한다. 알려진 비용은 전부 합산하며, 알 수 없는 비용을 0토큰 성공으로 바꾸지 않는다. 미완료 실행은 전체 24개에 대한 절감 성과로 발표하지 않는다.

결과는 results/effort-followup 아래에 저장한다. manifest는 배타적 생성으로 기존 실행의 덮어쓰기를 막고, 데이터·원본 HIGH 요청·실제 prompt/stdin·실행 소스·지시문 해시, CLI 버전과 모든 인자를 기록한다. 각 요청과 원본 stdout JSONL을 보존한다. 중간 중단 후 같은 실험을 자동 재개하거나 재호출하지 않는다.

## 채점과 감사

양끝 공백 제거, Unicode NFC, CRLF 정규화 후 정답과 정확히 비교한다. 입력+출력이 전체 토큰이며 reasoning은 출력 안에 포함된다. cached input은 별도로 기록한다. 항목별 실제 호출 비용을 사용하고 추정 토큰을 만들지 않는다.

완료 후 별도 감사기가 LOW 24개 원본 JSONL과 HIGH 24개 원본 JSONL을 대조한다. 각 팔의 전체 비용, 유형별 비용·정답 수, 둘 다 정답/LOW만 정답/HIGH만 정답/둘 다 오답을 공개한다. 실패한 문제도 모두 분모에 포함한다. 출력 안의 reasoning 비중과, 입력 및 나머지 출력을 고정했을 때 reasoning을 전부 없애는 가정의 회계상 상한도 별도로 표시한다. 이 상한은 달성한 성과가 아니다.

단건 LOW의 전체 토큰 감소율과 정답 수를 함께 보고한다. 품질이 떨어지면 비용-품질 교환관계로 보고하고, 품질을 유지했다고 표현하지 않는다. 24문제·각 팔 1회·후행 LOW라는 제한 때문에 일반적 최적 effort 판정이나 통계적 유의성을 주장하지 않는다. 결과를 사용해 만든 후속 라우터는 별도 데이터에서 검증해야 하며, 이 데이터에 대한 사후 oracle 선택을 배포 가능한 라우터 성과로 제시하지 않는다.

## 실행

    node scripts/measure-effort-followup.mjs
    node scripts/audit-effort-followup.mjs

각 파일을 작성할 때는 모델을 호출하지 않는다. 실행기는 v3의 완료 여부와 해시를 검증한 뒤에만 LOW 호출을 시작한다.
