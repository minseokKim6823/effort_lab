# 토큰 절약 개선 설계

기존 실험은 총토큰 차이가 0.21%였고 자동 선택의 출력 토큰은 오히려 많았다. 원인을 숨기지 않고 **문맥 비용**과 **effort 비용**을 분리했다.

## 제품의 동작

1. 문제의 텍스트·길이·추론 신호로 low/medium/high를 선택한다. 분류 모델을 호출하지 않아 라우팅 토큰은 0이다.
2. 앱의 답변 전용 호출에는 짧은 지시문을 사용한다. 파일 수정·터미널·앱 도구는 사용하지 않는다.
3. 정답 검증에 실패하면 다음 effort로 올린다. 시작이 high이면 한 번으로 끝난다. 낮은 effort부터 시작할 때 최대 세 번이다.
4. 실패한 호출까지 입력·출력·캐시·추론 토큰과 시간을 모두 기록한다. 정답은 검증기에만 전달된다.
5. 외부 검증 기준이 없는 자유 서술 답변은 UNVERIFIED다. 정확하다고 표시하지 않는다.

문맥 교체는 공식 Codex의 [model_instructions_file 설정](https://learn.chatgpt.com/docs/config-file/config-reference)을 사용한다. 사용자 Codex 설정 파일은 바꾸지 않는다. 이 정책은 앱의 **독립적인 텍스트 문제**에 적용된다. 실제 저장소를 수정하는 코딩 에이전트의 지시문을 제거해도 된다는 의미는 아니다.

## 네 비교군

| 비교군 | 문맥 | effort | 실패 시 재시도 |
|---|---|---|---|
| DEFAULT_HIGH | 기존 CLI 기본 문맥 | high | 없음 |
| HIGH | 답변 전용 문맥 | high | 없음 |
| LOW | 답변 전용 문맥 | low | 없음 |
| ADAPTIVE | 답변 전용 문맥 | 로컬 규칙 선택 | 다음 effort |

- DEFAULT_HIGH → HIGH는 같은 effort에서 문맥 교체의 효과를 본다.
- HIGH → ADAPTIVE는 같은 문맥에서 effort 정책의 효과를 본다.
- DEFAULT_HIGH → ADAPTIVE는 전체 제품 변경의 효과를 본다.
- LOW는 무조건 낮추는 정책만으로도 충분한지 확인하는 비교군이다.
- high 자체도 정답을 보장하지 않는다. 토큰 감소와 정답률을 함께 읽어야 한다.

## 확장 실험

코드로 정답을 계산한 12개 합성 문제를 사용한다. 변환 4개, 계산 4개, 조합·최적화 4개다. 난수 시드 20260923과 데이터 버전을 고정하고 각 문제를 세 번 반복한다. 총 144개의 전략 실행에 재시도가 추가된다. 실행 순서는 문제와 반복에 따라 순환한다.

배낭 정답은 완전 탐색과 동적 계획법, 선행 작업 순서 수는 순열 탐색과 부분집합 동적 계획법으로 서로 대조한다. 생성기 `scripts/generate-challenges.mjs --check`는 데이터 재현성을 검사한다. 입력과 정답은 실험 시작 전에 커밋한다. 실패 사례를 제외하거나 유리한 실행만 보고하지 않는다.

원본 JSONL의 usage·답변·정답 판정·전략별 합계는 별도 스크립트로 다시 감사한다. 신뢰구간은 12개 문제를 묶음으로 재표집한다. 같은 문제의 세 반복과 네 전략을 독립적인 144개 문제로 세지 않는다. 신뢰구간은 이 작은 합성 표본에 대한 보조 지표이며 실제 업무의 일반화 또는 품질 비열등성을 증명하지 않는다.

## Windows 데스크톱

Electron이 포함된 Java 21 런타임으로 Spring Boot를 시작한다. React 정적 파일은 JAR에서 같은 출처로 제공된다. 임의의 비어 있는 loopback 포트와 실행마다 생성한 토큰으로 앱 세션을 보호한다. 다른 로컬 페이지의 요청과 Origin: null 요청은 거부한다.

데이터는 설치 폴더가 아닌 %APPDATA%/effort-lab-desktop에 저장한다. 앱을 종료하면 자신이 시작한 백엔드와 하위 CLI도 종료한다. 로그인은 기본 메뉴에서 진행하며 사용자의 Codex 인증 저장소를 그대로 사용한다. Java, Node.js 또는 Codex를 별도로 설치할 필요가 없다. 계정·API 키·기존 실험 DB는 배포 파일에 넣지 않는다.

## 남아 있는 한계

현재 라우팅은 학습된 난이도 예측기가 아니라 키워드 규칙이다. 짧지만 어려운 문제를 완벽히 분류하지 못한다. 정확한 정답을 미리 아는 실험의 재시도 효과를 자유 서술 업무로 일반화할 수 없다. 구독의 실제 사용량을 읽지만 토큰 합계는 결제 금액이나 남은 구독 한도와 같지 않다.
