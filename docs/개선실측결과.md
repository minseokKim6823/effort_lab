# 확장 실험의 관찰 결과

문맥 축소는 완료된 1회차에서 같은 정답 수로 총토큰을 **46.27% 줄였다**. 자동 effort 선택은 짧은 문맥 high보다 토큰을 **4.31% 더 사용**했고 정답 수가 적었다. **자동 effort 개선은 입증하지 못했다.**

## 실험 상태

- 모델: `gpt-5.6-luna`, Codex CLI 0.153.4, ChatGPT 구독 로그인. API 키 없이 실행했다.
- 정책: `rules-1.1`; 문맥: `answer-only-v1`; 데이터: `challenge-12-seed20260923-v1`.
- 사전 계획: 12문제 × 3반복 × 4전략 = 144개 전략 실행과 필요한 재시도.
- 실제 종료: `ERROR`, 84/144개 기록. 구독 사용량 한도에 도달해 마지막 호출의 usage를 받지 못했다.
- 알려진 원본 85개 호출을 대조했으며, 사용량 미확인 전략 실행은 1개다.
- 첫 72개 완료 실행 뒤 호출 전 로컬 I/O 오류가 있어 완료된 결과를 보존한 채 재개했다. 재개 후에도 모델·정책·문제는 같았다.
- 전체 실험의 `comparable=false`, `savingsPercent=null`, `overallSavingsPercent=null`을 유지한다. 누락된 사용량을 0으로 가정하지 않는다.

[실험 시작 조건](../results/v2/manifest.json), [호출 전 중단 기록](../results/v2/interrupted-report.json), [재개 기록](../results/v2/resume-manifest.json), [종료 원본](../results/v2/report.json)을 보존했다.

## 완료된 첫 번째 반복

네 전략이 모두 끝난 1회차의 12문제를 빠짐없이 집계했다. 어려운 문제나 실패를 제외하지 않았다. 3회 전체 계획을 마친 실험으로 해석해서는 안 된다. 2회차의 알려진 결과도 원본과 아래 실패 목록에 남아 있다.

| 방식 | 입력 토큰 | 출력 토큰 | 총토큰 | 정답 | 재시도 |
|---|---:|---:|---:|---:|---:|
| 기존 문맥 high | 82,263 | 4,576 | 86,839 | 11/12 | 0 |
| 짧은 문맥 high | 39,900 | 6,756 | 46,656 | 11/12 | 0 |
| 짧은 문맥 low | 39,966 | 4,127 | 44,093 | 11/12 | 0 |
| 짧은 문맥 자동 | 42,900 | 5,767 | 48,667 | 10/12 | 1 |

입력+출력을 합산하고 캐시 입력을 포함했다. 추론은 출력의 일부라서 다시 더하지 않았다. 검증 실패 후 재시도한 비용도 포함했다.

- **문맥 교체:** 기존 문맥 high → 짧은 문맥 high, 46.27% 감소. 정답 수는 둘 다 11/12지만 틀린 문제가 동일하지는 않다.
- **effort 선택:** 짧은 문맥 high → 자동, 4.31% 증가. 정답은 11/12 → 10/12.
- **전체 변경:** 기존 문맥 high → 자동, 43.96% 감소. 정답 수도 감소했으므로 품질을 유지한 절감으로 주장하지 않는다.
- 같은 1회차에서 항상 low도 11/12였다. 현재 규칙 라우터가 단순한 low 정책보다 우수하다는 근거도 없다.

## 재현과 독립 검증

문제의 정답은 [생성기](../scripts/generate-challenges.mjs)로 계산하고 첫 호출 전에 커밋했다. 정답은 모델에 보내지 않는다. 배낭과 선행 작업 순서는 서로 다른 알고리즘으로 정답을 교차 확인한다.

```powershell
node scripts/generate-challenges.mjs --check
node scripts/audit-observed-results.mjs
node scripts/write-observed-report.mjs
```

[감사 스크립트](../scripts/audit-observed-results.mjs)는 알려진 **모든 호출**의 usage·최종 답변·정답 판정·재시도 비용·전략별 합계를 원본 JSONL과 비교한다. [감사 결과](../results/v2/observed-audit.json)는 `PARTIAL_AUDIT_PASS`이며 실험 완료를 뜻하지 않는다. [1회차 집계](../results/v2/observed-metrics.json)는 소개 화면과 같은 데이터다.

## 해석의 범위

12개 합성 문제의 1회차 관찰이다. 독립적인 검증 세트에 대한 일반화나 품질 비열등성을 증명하지 않는다. 한도 초기화 후 고정된 반복 실험을 새로 완료해야 한다. 임의로 성공 실행을 골라 전체 실험으로 포장하지 않는다.

실측과 로컬 빌드·패키징을 병행했으므로 지연 시간에는 자원 경쟁이 섞일 수 있다. 실행 속도 개선은 주장하지 않는다. 토큰 감소율은 요금 절감액이나 남은 구독 한도와 동일하지 않다.

다음 개선 과제는 별도의 학습용 문제에서 규칙을 조정하고, 수정에 사용하지 않은 문제에서 항상 low/high와 다시 비교하는 것이다. 현재 실패 결과를 본 뒤 같은 문제에서 좋은 수치가 나올 때까지 재시도하는 방식은 사용하지 않는다.
