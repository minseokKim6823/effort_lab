# 추론 예산 연구: 무엇을 예측해야 토큰이 실제로 줄어드는가

조사일: 2026-10-04. 목적은 **작업별 품질을 유지하면서 라우팅·검증·실패·재호출을 포함한 총토큰을 줄이는 것**이다. 논문의 절감률은 이 앱의 실측값이 아니다. 현재 키워드 규칙을 학습된 라우터라고 부르지 않는다.

## 1. 기존 방식의 실패 원인

기존 보고서의 완료된 첫 반복만 사용한다. 12문제, 같은 모델 `gpt-5.6-luna`, 짧은 문맥, 각 전략 1회다. 전체 3회 반복은 구독 한도로 중단됐으므로 반복 실험이 완료됐다고 해석하지 않는다.

| 전략 | 입력 | 출력(추론 포함) | 총토큰 | 정답 |
|---|---:|---:|---:|---:|
| high 고정 | 39,900 | 6,756 | 46,656 | 11/12 |
| low 고정 | 39,966 | 4,127 | 44,093 | 11/12 |
| 기존 자동 effort | 42,900 | 5,767 | 48,667 | 10/12 |

자동 선택은 high보다 4.31% 비싸고 정답도 적다. low 고정은 총토큰이 5.49% 적었고, high와 같은 11문제를 맞히고 같은 1문제를 틀렸다. 결과를 미리 보고 LOW/HIGH 중 가장 싼 정답을 고르는 가상 oracle도 43,939토큰, 11/12 정답, 5.82% 절감에 그쳤다. 항상 low보다 추가로 아낄 수 있었던 양은 전체 154토큰뿐이다. 이 관측 후보들에서는 더 복잡한 라우터를 만들 유인이 작으며, oracle 결과는 배포 성능이 아니다.

high의 입력 비중은 85.52%다. **입력을 고정한다는 가정에서** 출력 전체를 제거해도 최대 감소는 14.48%이고, 추론 6,616토큰만 모두 제거하는 가상 상한은 14.18%다. 이는 가능한 제품 성과가 아니라, 현재 짧은 정답형 작업에서 effort만 바꿔 얻을 수 있는 여지를 설명하는 산술 진단이다. 추론을 없애도 품질이 유지된다는 뜻이 아니다.

계산 4문제에서 medium 첫 호출의 합은 14,239토큰으로 high의 14,252토큰보다 단 13토큰 저렴했다. 모듈러 점화식의 재호출 1회가 3,785토큰을 추가해 자동 정책의 계산 비용은 18,024토큰, high 대비 26.47% 증가했다. 반면 같은 high라도 조합 추론을 틀렸으므로 “어려우면 high”만으로 정답이 보장되지 않는다. [원본 보고서](../results/v2/report.json)와 [재현 가능한 진단](../scripts/analyze-effort-opportunity.mjs)을 함께 확인한다.

## 3. 재시도의 손익분기점

한 번의 낮은 effort 비용을 C_low, high 비용을 C_high, 낮은 effort가 **신뢰할 수 있는 검증을 통과해 재호출을 피할 확률**을 p, 라우팅·검증 비용을 V라고 하자. 실패하면 high를 한 번 실행하는 단순한 모델에서는:

```text
기대 총비용 = C_low + V + (1 - p) × C_high
처음부터 high보다 저렴할 조건: p > (C_low + V) / C_high
```

이는 비용 판단식이며 정확도 보장이 아니다. 실제로는 실패한 문제의 high 비용이 평균 high 비용보다 클 수 있으므로 조건부 비용도 추정해야 한다.

기존 전체 평균 비용을 대입하고 V=0으로 두면 필요한 통과 확률은 약 94.51%다. 입력 비용이 대부분이라 값싼 첫 시도가 충분히 싸지 않다. 성공률 추정 없이 low → medium → high를 고정 순서로 실행하면 오히려 비싸질 수 있다.

정답이 주어진 실험의 채점기는 실제 사용자 작업의 검증기와 다르다. `EXACT`의 정답을 정책 입력에 넣지 않으며, `NONE`에서는 성공을 주장하거나 정답 기반 재시도를 할 수 없다. 코드 테스트·스키마·필수 조건 검사는 각각 자신이 검사하는 범위까지만 품질 근거가 된다.

## 4. 다음 개별 effort 정책의 설계

1. **예측 대상:** 문제 자체의 추상적인 난이도가 아니라, 해당 모델에서 각 effort의 성공 가능성과 총토큰을 추정한다. 모델·CLI·프롬프트 버전도 프로파일에 포함한다.
2. **입력 특징:** 작업 유형, 입력 길이, 숫자·조건·반복 계산의 구조, 요구 출력 길이, 검증 가능성을 사용한다. 평가 ID와 정답은 특징에서 제외한다.
3. **선택:** 품질 기준을 충족할 근거가 있는 후보 중 예상 총비용이 가장 작은 effort를 고른다. 판단용 LLM을 추가한다면 그 호출의 모든 토큰도 비용에 넣는다.
4. **재시도:** 실패 유형과 조건부 성공률을 사용한다. 중간 effort를 거치는 편이 이득이라는 근거가 없으면 자동으로 세 단계를 모두 실행하지 않는다.
5. **불확실성:** 낮은 effort의 성능 근거가 없는 작업에서는 절감을 확정하지 않는다. 위험 수준과 사용자가 요구한 정확도 기준을 우선한다.
6. **배포 조건:** 항상 low, 항상 high, 기존 규칙보다 비용·품질의 조합이 나아지는지 분리된 평가에서 확인한 뒤 기본 정책으로 승격한다.

현재 데이터로 학습·보정·최종 평가를 모두 수행하면 과적합이다. 예를 들어 사전에 고정한 정책이 독립적인 4개 문제를 모두 맞혀도, 이항 모형의 단측 95% 오류율 상한은 약 52.7%다. 12개 전부 정답이어도 약 22.1%다. 식은 `1 - 0.05^(1/n)`이며, 임계값을 같은 데이터에서 골랐거나 데이터가 독립적이지 않으면 이 단순 계산도 보장으로 쓸 수 없다.

따라서 소수 기록의 100%를 신뢰도 100%로 저장하는 새 라우터는 도입하지 않는다.

## 5. 실험과 성과 판정

### 개별 effort 연구

- 기존 v2는 개발·진단 자료다. 관측 결과를 보고 가장 싼 정답을 선택하는 oracle 분석은 달성 가능한 여지를 살피는 참고선이며 배포 가능한 정책 결과가 아니다.
- 최종 평가는 학습과 다른 문제뿐 아니라 다른 문제 유형·출력 길이에서도 수행해야 한다. 새 숫자로 만든 같은 유형은 “새 인스턴스” 검증이지 유형 밖 일반화 검증이 아니다.
- 비교군: 고정 low / medium / high, 기존 규칙, 새 비용·품질 기반 정책. 처음에는 관측 가능한 비교군부터 확보하며, 빠진 medium 결과를 추정값으로 채우지 않는다.
- 같은 모델·문맥·검증기·도구 조건을 유지하고 실행 순서를 섞는다. 추가 router·verifier·retry 비용을 포함한다.
- 총토큰, 추론 토큰, 입력·캐시 입력, 정답 수, high만 정답인 문제와 새 정책만 정답인 문제, 실패 및 사용량 누락을 모두 공개한다.
- 절감 목표를 맞출 때까지 평가 문제를 바꾸거나 유리한 반복만 선택하지 않는다. 품질이 떨어지면 토큰이 줄어도 품질 유지 성과로 승격하지 않는다.

### 공통 입력 비용 연구

별도의 [묶음 실험 계획](배치실험계획.md)으로 고정 high에서의 입력 공유 효과를 평가한다. 이 기능은 독립된 여러 작업이 있을 때만 적용할 수 있다. 개별 요청의 effort 선택 문제는 위 연구와 별도로 남는다.

## 7. 후속 실측으로 확인한 범위

2026-10-04에 사전 고정한 24문제에서 개별 high는 95,440토큰·24/24 정답, 개별 low는 98,979토큰·19/24 정답이었다. low의 추론 토큰은 줄었지만 입력 토큰이 늘어 전체 비용과 정답이 모두 악화됐다. 낮은 effort가 실제 총비용을 줄이는지와 품질을 유지하는지는 별도로 검증해야 한다는 가설을 뒷받침한다. [실험 결과와 원본](개별-effort-후속결과.md)에 시점·캐시 교란과 문제 유형의 한계를 기록했다.

같은 24문제를 high로 네 개씩 묶으면 95,440에서 32,665토큰으로 65.77% 줄고 24/24 정답을 유지했다. 이는 [묶음 실측](묶음실측결과.md)의 결과이며 위의 개별 effort 정책 성과로 합산하지 않는다.
